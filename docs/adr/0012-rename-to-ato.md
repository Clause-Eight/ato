# 12. Rename the product to ATO

Date: 2026-10-31 · Status: accepted

## Context

On 2026-10-31 the owner decided to rename the product from pii-eu to ATO. The old name described a category
(personal data in the EU) rather than a product, and it is spelled differently in prose, commands, environment
variables and code (`pii-eu`, `PII_EU_`, `piiEu`).

"ATO" is also a common abbreviation for "account takeover" in security. To avoid that reading, the first mention
on every page says "ATO, Clause Eight's EU personal-data scanner"; after that, "ATO" alone.

Users of 1.x have files, comments, CI settings and code scanning alerts that carry the old name. The
compatibility rules (docs/COMPATIBILITY.md) allow removing a name only in a major release, after it has been
deprecated.

## Decision

1. The product is **ATO**, written in capitals in prose, "a Clause Eight tool". The command and binary are `ato`.
   The release is **2.0.0**, a major version, because commands, file names and report identifiers change.
2. What changes:
   - The command `pii-eu` becomes `ato`; the Go module `github.com/Clause-Eight/pii-eu` becomes
     `github.com/Clause-Eight/ato/v2`, with the command in `cmd/ato`. The GitHub repository is renamed to
     `Clause-Eight/ato` by the owner; GitHub redirects the old URL.
   - Release archives are named `ato_<version>_<os>_<arch>` instead of `pii-eu_…`.
   - Default files: `.ato.toml` and `.ato-baseline.json`. Inline comments: `ato:ignore <reason>`.
   - Reports: JSON `tool.name` is `ato` and every JSON schema goes to version `2.0`; the SARIF driver is `ATO`;
     the SARIF partial fingerprint key is `ato/v1`; GitLab Code Quality check names are `ato/<detector>`; error
     and warning messages start with `ato:`; HTML and Markdown reports say "Generated by ATO".
   - The GitHub Action, the pre-commit hook id, the GitLab and Bitbucket templates and their variables
     (`ATO_VERSION`, `ATO_MIN_CONFIDENCE`), and the benchmark script's labels.
3. What stays:
   - Detector names and SARIF rule IDs, flags, settings keys, exit codes and every JSON field.
   - Fingerprints and the baseline format, so baselines written by 1.x keep working.
   - The synthetic mark. Its salt and the seed of `fix` keep the string `pii-eu`, because changing either would
     stop values written by 1.x from being recognised, or change the values `fix` writes.
   - Earlier ADRs and the benchmark results in `bench/compare/results` keep the old name as a record.
4. Compatibility in 2.x, each deprecated and removed no earlier than 3.0:
   - `.pii-eu.toml` and `.pii-eu-baseline.json` are read when the new file is absent, with a warning on standard
     error. `ato baseline` writes the new file name.
   - `pii-eu:ignore` comments are honoured, with one warning per scan.
   - SARIF results carry `piiEu/v1` next to `ato/v1`, with the same value, so GitHub code scanning keeps matching
     the alerts that 1.x opened.
   - `ato map --diff` reads data maps saved by 1.x.
   - The `pii-eu` pre-commit hook id runs `ato`. The CI templates read `PII_EU_VERSION` and
     `PII_EU_MIN_CONFIDENCE`, with a warning, when the `ATO_` variables are not set.
   - The `ato` binary reads no environment variables, so it has none to fall back on. The test-only
     `PII_EU_UPDATE_GOLDEN` becomes `ATO_UPDATE_GOLDEN` without a fallback.

The complete list is in docs/COMPATIBILITY.md, "Changes in 2.0".

## Consequences

- Scripts and CI that call `pii-eu` must call `ato`; nothing else has to change at once.
- Readers of the JSON reports must accept `schema_version` `2.0` and `tool.name` `ato`; no field changed.
- GitLab shows Code Quality findings under new check names; it matches findings by fingerprint, which is
  unchanged.
- Go requires the module path of a `v2.x.x` tag to end in `/v2`, so the module path is
  `github.com/Clause-Eight/ato/v2` and `go install github.com/Clause-Eight/ato/v2/cmd/ato@latest` works once a
  v2 tag exists.
- The warnings add lines on standard error for users who have not renamed their files; standard output and
  every report are unaffected.
