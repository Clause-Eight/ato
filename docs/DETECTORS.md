# Detectors

Generated by `ato detectors --markdown`; a test fails when this file is out of date.

Base confidence is what a valid match gets on its own. A keyword on the same line or the line before raises it one step; a test or fixture path lowers it one step; a published sample value is always low. The default `--min-confidence` is medium.

Keywords are the identifier's own names. Concepts add the shared words for that kind of data in all 24 EU languages, from `internal/detectors/keywords/`. Detectors marked off by default run when switched on in `[detectors]` or when their country is selected with `--countries`.

Schema and model fields whose names say they hold special-category data (GDPR Art. 9: health, genetic, biometric, racial or ethnic origin, political opinions, religious or philosophical beliefs, trade union membership, sex life or sexual orientation) are reported as `special-category` findings at medium confidence. Switch them off with `special-category = false` under `[detectors]`.

Tables and models holding personal data can also be checked for an erasure path (GDPR Art. 17: a delete, an anonymising update or a cascade from an erasable parent) and a retention limit (Art. 5(1)(e): a time-based delete, a TTL, a partition drop, a Redis key expiry or a search index policy that deletes). Switch the `no-erasure-path` and `no-retention` findings on under `[detectors]`; they are off by default because data can be removed in ways the code does not show. `ato map` always shows both.

Log, print, error-tracker and analytics calls in Go, Python, JavaScript and TypeScript, Java, Kotlin, Ruby and PHP that are passed a field whose name says it holds personal data (`user.email`), a whole request body (`req.body`) or a user-like object (`currentUser`) are reported as `log-sink` findings, with the sink (log, error-tracker or analytics) and the data category: medium confidence for a named field or a request body, low for a whole object or an online identifier. Session replay that scripts, pages or templates set up to record form inputs (`maskAllInputs: false`, `defaultPrivacyLevel: 'allow'`, `data-hj-allow` on a form field and similar) is reported with the sink `session-replay`. Switch them off with `log-sink = false` under `[detectors]`.

Files that hold personal data as a whole are reported as file findings: `database-dump` for SQL dumps (mysqldump, pg_dump plain and custom format, sqlite3 `.dump`, `.sql`, `.dump`, `.bak`, also inside `.gz`) with rows inserted into columns whose names say they hold personal data, naming the table and columns, never a value (high confidence when the file names the tool that wrote it, medium for 20 or more rows, low for a few rows of seed data); `document-author` for a person's name in the author metadata of Office Open XML and OpenDocument files, masked; `photo-location` for JPEG, TIFF, PNG, WebP and HEIF images with an EXIF GPS position, masked; and `id-document-scan` for images and PDFs whose file name says they are a passport, an identity card, a driving licence or a residence permit, in the EU languages (medium confidence, low for an ambiguous word or a folder name). ATO does no OCR: the content of an image is never read as text, and a PDF's text is searched only for machine readable zones (`mrz`). Office documents, PDFs and pg_dump archives stay listed as not read in full. Switch any of them off under `[detectors]`.

## Terraform data stores

`ato scan` reads the data stores declared in `.tf` files, without running Terraform, and reports these checks as `infra` findings. A finding is high when the store is linked to personal data (a tag such as `data_classification = "pii"` or `pii = true`, or a name that matches a table or model in the inventory) and medium otherwise. A setting that comes from something the code does not show, such as a variable without a default, is never read as a failure: it is reported at low confidence, and only for linked stores. Switch a check off under `[detectors]`, for example `tf-no-retention = false`.

| Name | Finding | Reported when | Supports |
|---|---|---|---|
| `tf-unencrypted` | Data store without encryption at rest | encryption at rest is switched off, or not set where the service leaves it off | GDPR Art. 32(1)(a) |
| `tf-no-retention` | Data store without a retention limit | nothing expires the data: no lifecycle rule, retention period or TTL | GDPR Art. 5(1)(e) |
| `tf-non-eea-region` | Data store outside the EEA | a region is outside the EEA; one step lower when the country has an EU adequacy decision | GDPR Chapter V |
| `tf-public` | Data store open to the public | a public ACL, a grant to everyone or an internet-facing endpoint opens the store | GDPR Art. 32(1)(b) |

Resource types read as data stores:

- AWS: `aws_cloudwatch_log_group`, `aws_db_instance`, `aws_docdb_cluster`, `aws_dynamodb_table`, `aws_ebs_volume`, `aws_efs_file_system`, `aws_elasticache_replication_group`, `aws_elasticsearch_domain`, `aws_kinesis_stream`, `aws_opensearch_domain`, `aws_rds_cluster`, `aws_redshift_cluster`, `aws_s3_bucket`, `aws_sns_topic`, `aws_sqs_queue`
- Google Cloud: `google_bigquery_dataset`, `google_bigquery_table`, `google_firestore_database`, `google_logging_project_bucket_config`, `google_pubsub_topic`, `google_redis_instance`, `google_spanner_instance`, `google_sql_database_instance`, `google_storage_bucket`
- Azure: `azurerm_cosmosdb_account`, `azurerm_log_analytics_workspace`, `azurerm_mssql_database`, `azurerm_mysql_flexible_server`, `azurerm_postgresql_flexible_server`, `azurerm_redis_cache`, `azurerm_storage_account`, `azurerm_storage_container`

Module calls: a local module (`source = "./db"`) whose folder is scanned is read as its own folder. Any other `module` block (registry, git or a local folder outside the scan) is not read inside. When its source or label names a kind of store (`terraform-aws-modules/rds/aws`, `patients_db`) or it passes arguments that look like store settings (`storage_encrypted`, `retention_in_days`, `kms_key_id`, `publicly_accessible`), it is listed in the inventory's `stores` as type `module`, with its source, those arguments by name and every setting unknown. A module call gives no scan findings.
